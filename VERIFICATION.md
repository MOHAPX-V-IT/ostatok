HTTP-тесты поднимают настоящий Uvicorn на loopback-порту, используют httpx и независимые psycopg-соединения с отдельной БД `*_test`. Это не ASGI mock, не SQLite и не in-memory inventory. Fixture проверяет имя тестовой БД и отличие от app database перед пересозданием schema public. App-данные тестами не сбрасываются.

## Что проверяли девять сценариев

1. 20 одновременно начатых HTTP reserve при 7 доступных единицах: ровно 7 успешных, 13 stock conflicts; available=0/reserved=7, без лишних документов и движений.
2. Bulk rollback при недостатке второй позиции; два конкурентных bulk с противоположным порядком items без deadlock/oversell.
3. Восемь конкурентных запросов с одним idempotency key дают один резерв; другой body — 409; shared client_id между ключами, разные клиенты и endpoints корректно разделяют scope.
4. Confirm/cancel, replay и изменённый body, запрет отмены подтверждённого резерва; ledger sums совпадают с балансом, повтор не создаёт второе движение.
5. Конкурентные expiry sweep и поздний confirm: ровно одно освобождение, ни одного списания, сохранённый expired-документ.
6. Confirm ждёт stock lock дольше TTL и после получения lock отклоняется, освобождая остаток.
7. API-key 401/403, owner check, отзыв и последний admin; pagination, bounds, уникальность items, Problem JSON/request ID, OpenAPI/Swagger.
8. Пустая схема, повтор миграции на существующих данных, additive V1→V2, checksum mismatch; seed не удваивает приход и не пополняет уже занятые единицы.
9. DB CHECK запрещает отрицательные available/reserved; non-superuser connection, HTTP 1 MiB boundary и отсутствие переданного секрета в validation error.

Число конкурентных запросов и время тестового прохода описывают тест, не производительность продукта или эксплуатационный SLA.

## Локальный preview

API запущен на `127.0.0.1:4511`. `/health`, `/docs`, `/openapi.json`, `/`, `/console/stockroom.js` ответили HTTP200. Admin `/api/me` и чтение реальных seed balances проверены; новый ключ хранится только в ignored `data/demo-key.txt`. В БД сохраняется hash, не открытый API secret.

Визуальную CUA-проверку консоли выполняет координатор; HTTP200 сам по себе не считается визуальной проверкой. Демо использует синтетические SKU и движения.

## Не выполнялось

- Docker image build и `docker compose up`: Docker здесь не предполагался доступным. Проверена только конфигурация/синтаксис; runtime container/non-root healthcheck не выдаются за выполненный тест.
- GitHub Actions run: workflow с PostgreSQL 18 service и отдельной non-superuser ролью подготовлен, запуск после публикации ещё не подтверждён.
- Нагрузочный benchmark, длительная эксплуатация, failover кластера, резервное восстановление и внешний deployment.

## Итоговая проверка координатора — 18.10.2026

В реальном in-app браузере созданы резерв двух SKU, подтверждение отгрузки, приход и отдельная отмена. Недостаток остатка вернул 409 и понятное сообщение без изменения баланса. После перезапуска сохранились 25 доступных блокнотов и 4 ручки, без открытого резерва. Клавиатурные стрелки переключают вкладки с aria-selected и фокусом.

Все три консоли визуально осмотрены в desktop-окне и внутри iframe шириной 390 CSS px: это проверка адаптивной вёрстки, а не физического мобильного устройства. Выполнен выборочный клавиатурный сценарий, не полный WCAG-аудит. Снимок — `docs/interface.png`; ключи не сохраняются в браузере и не попали на снимки.

Общий набор из **23 регрессионных проверок логики консолей** выполнен в Node VM с DOM/network-заглушками против фактических JavaScript-исходников трёх продуктов. Проверены подтверждённая запись при ошибке последующего GET (сообщение не предлагает повторять уже сохранённую операцию), сохранение idempotency key при неопределённом исходе POST и защита от устаревших ответов. Это отдельные logic tests, не 23 браузерных E2E и не дополнительные тесты PostgreSQL.

Общий Windows-launcher реально остановил/запустил приложения с прежней БД; миграции повторно не изменили существующие данные. Архитектура и критические места рассмотрены соседним агентом. В Пересменке замечания по конкурентному отзыву администраторов и выборке тяжёлых CSV устранены до финального запуска. Ревью не заменяет независимый аудит безопасности.
